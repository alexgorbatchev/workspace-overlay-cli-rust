Run `workspace-overlay overlay mount` in a directory with `workspace-overlay.toml` in its ancestry, or supply `--config path/to/workspace-overlay.toml`. Require Linux with accessible `/dev/fuse`, and the `git`, `findmnt`, and `fusermount3` commands on `PATH`; `fuser` (psmisc) on `PATH` names the processes that keep a mount busy.

- `overlay mount`: Serve every configured project and its Git worktrees in the foreground. Accept no positional arguments. SIGINT/SIGTERM stops all mounts and is a clean stop even while a check is running. A mount failure cancels the group and only the failing project's error is reported. Refuse a target mounted with another filesystem type, with or without `--replace`; refuse a target that already has an overlay mount unless `--replace` is given. External unmount of a primary project stops that project's mounts; external unmount of a linked worktree suppresses it until it is unregistered and registered again.
- `overlay unmount`: Stop selected owner processes and clean their mounts and managed Git exclusions. Recover recorded mounts from terminated owners. Succeed for unmounted targets; refuse filesystems other than `fuse.workspace-overlay`.
- `overlay status`: Print one tab-separated target path and filesystem type per target, including recorded mounts that Git no longer lists. Print `unmounted` for unmounted targets. With `--worktrees=false`, only discover primary projects but still list recorded mounts. Return exit 0 for unmounted targets.
- `--config` (string, default empty): Apply to all overlay commands. Empty discovers the nearest `workspace-overlay.toml` in the current or parent directories. Resolve configured project and source paths relative to the directory that holds the file; a file that is a symbolic link is held where the link is, not where it points.
- `--project` (string, default empty): Apply to all overlay commands. Empty selects all configured projects in sorted name order. A supplied name must exist in `[projects]`.
- `--worktrees` (bool, default true): Apply to all overlay commands. Include registered Git worktrees; mount monitors changes. Set `--worktrees=false` to mount primary projects only or omit fresh worktree discovery for status and unmount. Status and unmount still include recorded mounts; unmount stops the selected owner and all its mounts. Skip bare, prunable, and initializing worktree records. Projects without their own `.git` mount alone.
- `--replace` (bool, default false): Apply to mount only. Stop selected owners and recover stale registrations, then validate and mount. Refuse foreign filesystem replacement.
- `workspace-overlay skill`: Print this embedded guide verbatim, offline, without positional arguments or command-specific flags.
- `help [command]`: Print help for a command path. `--help` / `-h` (bool, default false) prints help on any command. Shell completion generation is disabled. Generated query paths are `workspace-overlay help`, `workspace-overlay help help`, `workspace-overlay help overlay`, `workspace-overlay help overlay mount`, `workspace-overlay help overlay unmount`, `workspace-overlay help overlay status`, `workspace-overlay help skill`, `workspace-overlay overlay help`, `workspace-overlay overlay help help`, `workspace-overlay overlay help mount`, `workspace-overlay overlay help unmount`, and `workspace-overlay overlay help status`. Each displays help and accepts `--help` / `-h` (bool, default false). The help command accepts `[COMMAND]...` (string command path). The root `workspace-overlay` displays help when called without arguments, as does `workspace-overlay overlay`.
- `--version` / `-v` (bool, default false): Apply to the root. Print the raw version followed by a newline: `0.1.0` for this unpublished Rust build.

Set the `AGENT` environment variable to `1`, `true`, or `yes` for compact help with a skill-reading alert; case and surrounding whitespace are ignored. Keep state files under `$XDG_STATE_HOME/workspace-overlay/`; when the `XDG_STATE_HOME` environment variable is unset, empty, or relative, use `~/.local/state/workspace-overlay/` from the platform home-directory lookup. Send progress and diagnostics to stderr.

An unmount fails while a process uses the mount (working directory, open file, or mapping inside it). This applies to `overlay unmount`, to `overlay mount --replace`, and to `overlay mount` stopped by SIGINT/SIGTERM. The error then reads `<unmount failure>; <target> is in use by:` followed by one line per process, `  pid <pid>: <command line> (in <working directory>)`, found with `fuser --ismountpoint --mount <target>`; a failed holder lookup identifies `list processes using <target>; fuser must be installed` and retains the underlying native error. The processes keep running and the command exits 1. After a stopped `overlay mount` the target stays mounted with no server and answers `transport endpoint is not connected`; the backing project is intact. End the listed processes, then run `overlay unmount`. When `AGENT` is unset or falsy and both stdin and stderr are terminals, the CLI instead prints the processes as a table on stderr and asks `Stop these processes and unmount? [y/N] ` on stdin; `y` or `yes` sends SIGTERM, sends SIGKILL to those still running after 3 seconds, and unmounts again; any other answer prints `<target> stays mounted. Run `workspace-overlay overlay unmount` to be asked again.` and reports the error above; `overlay unmount` asks the same question again, also for a mount whose `overlay mount` has exited. A terminal read failure, EOF, or SIGINT/SIGTERM received while waiting for an answer declines termination; a partial `yes` followed by an input failure does not authorize it. With `AGENT` truthy or without a terminal it never asks. Abbreviate home paths with `~/`, and the home directory itself with `~`. A failed operation prints only `ERR: <message>` to stderr and exits 1; a mistyped command line prints the command's usage to stderr before that line. Successful commands and clean shutdown exit 0.

Configure TOML `version = 1`, named `[projects.<name>]` tables with a required `path`, optional `[[markers]]` tables with required `glob`, `start`, and `end`, and ordered `[[overlays]]` tables with unique `name`, required `source`, required `projects` glob selectors, and optional `glob` (default `**/*`). `[defaults]` supplies `collision = "concat"` and `write = "most-specific"`; per-overlay fields inherit them. These are the supported policies. Use relative forward-slash globs without `.` or `..` components; recursive globs include dotfolders and selected ancestors. The directory that holds the configuration file, project paths, and overlay source paths are resolved through symbolic links, so a workspace reached through a symlink works and status and mount messages show resolved paths. The configuration file itself is not followed: when it is a symbolic link, its relative paths resolve from the directory the link is in, so a workspace can link to a configuration kept elsewhere. Reject unknown TOML fields, invalid patterns, overlapping mount targets, and sources inside their mount targets.

Read colliding text files as project bytes followed by matching overlay bytes in declaration order. Files matching configured `[[markers]]`, or otherwise the built-in rules, delineate each overlay section using start and end markers showing the overlay name and the relative path from the project directory where the file is accessed. The built-in rules apply without configuration, after any configured ones, the first match by file name or project path winning: `*.{md,markdown}` and `*.{html,htm,xml,svg}` use `<!-- BEGIN WORKSPACE-OVERLAY: {name} ({path}) -->` and `<!-- END WORKSPACE-OVERLAY: {name} ({path}) -->`; `*.{toml,yaml,yml,sh,bash,zsh,py,rb,env,env.*,*ignore}` and `{Dockerfile,Makefile}*` use `# BEGIN WORKSPACE-OVERLAY: {name} ({path})` and `# END WORKSPACE-OVERLAY: {name} ({path})`; `*.{go,ts,js,tsx,jsx,rs,c,cpp,h,hpp,java,css,scss,less}` use `// BEGIN WORKSPACE-OVERLAY: {name} ({path})` and `// END WORKSPACE-OVERLAY: {name} ({path})`. Other colliding text files are joined without markers. Only the project's own bytes go unmarked: a file that two or more overlays supply and the project lacks reads as marked overlay sections alone, and non-empty text written before the first marker creates the project copy, or fails with a permission error where the project has no directory for it. A file that one overlay alone supplies is served unchanged, without markers. When the calling process is Git, FUSE serves the project backing copy directly so Git status remains clean and Git checkouts succeed; a file Git creates goes into the project even where an overlay has a file of that name. Binary files are never joined: when a path exists in more than one layer and at least one copy is binary, reading it returns an explanation that lists every copy and how to resolve the collision, writes and truncation fail with a permission error, and each open logs `cannot merge <path>: binary collision` to stderr. Count a copy as binary when its first 512 bytes do not look like text. Serve a file that exists in one layer unchanged, as an ordinary file with shared memory mappings and no size limit. Merge directories recursively at every depth. A path that is a directory in one layer and a regular file in another returns an I/O error when accessed; the directory that contains it stays listable. Single symlinks retain their targets. Keep `.git` supplied exclusively by the backing project. Store skills in source `.agents/skills/` directories.

Write project-only files into the backing project. Write overlay files into their most-specific contribution. For marked colliding documents, edits in the project section persist to the project backing file and edits inside an overlay section persist to that overlay source; text after a section's end marker, such as an appended line, joins that section's source; modified documents with missing, broken, or reordered markers fail with a permission error. For unmarked colliding files, full-document saves preserve earlier contributions at the beginning and strip that prefix when saving the final layer; changed prefixes fail with a permission error. Support direct writes, append, truncate-on-open, and atomic saves (a temporary file renamed over the document); a marked document renamed over is split by its markers and each section saved to its source, and one with a missing or misplaced marker is refused with a permission error. Report one hard link per contributing layer for a merged file (`st_nlink` 2 or more), which makes Vim and Neovim write it in place with default settings. Stage merged writes until flush, fsync, or close. Truncating to zero clears only the final contribution. Metadata changes (`chmod`, `chown`, timestamps) do not need read access to the file. Opened merged files retain snapshots; subsequent opens use current sources. Merged files are held in memory and limited to 64 MiB total; opening a larger merged file or writing or truncating one past that size fails with "file too large".

Create entries in the project when the parent has project backing, otherwise in its most-specific overlay directory. Restricted globs must include new overlay paths. Unlinking a colliding file removes the project backing copy, falling back to the overlay layers and adding the path to Git exclusions. For a marked document the project section is then empty and every overlay section, including the first, stays marked until the mount stops or the project has the file again; non-empty text written before the first marker creates the project copy again with its former permissions, so removing a marked document and writing it again saves each section to its source; unlinking a path present only in overlays is rejected with a permission error to keep overlay sources protected. Entries created through a mount inside an overlay directory can be renamed to a free name and removed through that mount until it stops; a file renamed over an existing overlay document replaces its final contribution atomically, and that document stays protected. Edit source directories directly to delete or move their files. Stop overlays before recursively deleting a worktree; Git removal through a mount encounters protected paths. Directory moves across layers, links to merged files, rename flags, special-file creation, and native extended attributes are unsupported.

Cache project-backed directory entries for at most one second. Cache regular-file attributes and failed lookups only in namespaces that overlay patterns cannot supply; keep caller-dependent results uncached. Use native backing-directory notifications and mounted mutations to invalidate metadata; source reconciliation also invalidates entries. External changes can remain cached until their notification is processed, with the one-second timeout bounding staleness. Acquire at most 256 backing-directory watches and retain at most 1,024 entry names per watched directory; paths without watch coverage retain zero timeouts. A watcher error or rejected invalidation disables further caching and logs `disable metadata caching: <error>`; existing entries expire within one second. The caller's process identity is checked anew whenever routing depends on it.

Watch native Git common metadata and overlay source directories with native filesystem notifications, debounce relevant events for 200 ms, and reconcile every 30 seconds as a fallback. Discover checkout locations with `git worktree list --porcelain -z`; a listing that fails, at startup or while mounted, as it does while Git is still writing a new worktree, prints a warning with the native Git error and stderr, and is taken again up to three more times (after 100, 200, and 400 ms) before the project stops with that error; all worktrees use the original configured sources without local `.ai` links. Skip a linked worktree that lies inside another mount target, contains an overlay source, or has a path already mounted by another filesystem: report `Skipping worktree <path>: <reason>` on stderr, keep every project running, and try it again after Git unregisters and registers it. Source additions, removals, and newly created nested directories update the visible path index.

Temporarily add uniquely marked blocks to Git `info/exclude` for selected overlay paths absent from project backing. Keep tracked/backing collisions visible to Git, preserve user entries, and remove each mount's block on shutdown. Worktrees share their repository's exclude file. When caller is Git, FUSE serves project backing bytes directly so Git status remains clean and Git branch checkouts succeed. Record mount targets and exact managed blocks under `$XDG_STATE_HOME/workspace-overlay/` (default `~/.local/state/workspace-overlay/`), one set of files per workspace and project, removed on a clean stop; use an advisory owner lock and atomic registry replacement. `overlay mount --replace` stops selected owners and recovers stale registrations before mounting again, but refuses foreign filesystem replacement. After forced termination, use `overlay unmount` or `overlay mount --replace` to recover. Retain incomplete cleanup records; changed managed blocks cause an error for manual resolution.

From a configured workspace, run `workspace-overlay overlay mount`, inspect it with `workspace-overlay overlay status`, and stop it with `workspace-overlay overlay unmount`. Supply `--project alpha` to select that configured project.

For isolated verification from the CLI checkout, `just dev`, `just status`, and `just stop` invoke those commands. `just dev` creates or reuses `dev-workspace` and mounts all configured projects and worktrees; optional `--project alpha` narrows the selection. Run `just test-local` to exercise disposable end-to-end workspaces independently of `dev-workspace`. Edits remain in `dev-workspace` after stopping.

Use the developer helper `workspace-overlay-fixture [DIRECTORY]` to create or reuse a demonstration workspace; the optional native pathname `DIRECTORY` defaults to `dev-workspace`. It prints the exact absolute configuration pathname plus a newline on stdout, preserving native bytes for machine consumption. This machine pathname is not home-folded. A completed fixture is reused without rewriting edits; an existing incomplete or damaged directory is refused. First creation makes two projects, shared sources, isolated Git repositories and linked worktrees. A failed or cancelled creation leaves its assets without a completion marker. The helper's root accepts `--version` / `-v` (bool, default false; raw `0.1.0` plus newline), `--help` / `-h` (bool, default false), `skill` (this guide verbatim), and generated `help [COMMAND]...`. Help query paths are `workspace-overlay-fixture help`, `workspace-overlay-fixture help help`, and `workspace-overlay-fixture help skill`; their `--help` / `-h` flags have the same bool type and false default. Agent help starts with the corresponding skill-reading alert. Other positional arguments and flags are rejected. Both Rust binaries are unpublished local artifacts; development commands are in the repository's `AGENTS.md`.
